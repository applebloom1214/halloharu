# 할로하루 HalloHaru

할로하루는 사용자가 하루를 가볍게 기록하고, 부담 없는 공감과 웃음을 주고받을 수 있는 하루 기록 서비스입니다.

## 배포

[할로하루 서비스 바로가기](https://halloharu.vercel.app)

## 프로젝트 목적

대부분의 SNS는 뛰어난 외모, 능력, 인맥, 화려한 일상처럼 보여줄 것이 많은 사람에게 유리합니다.

반면 평범한 일상을 보내는 사람들은 글을 올려도 충분한 반응을 받기 어렵고, 무플과 무관심이 반복되면 점점 기록의 흥미를 잃게 됩니다.

할로하루는 평범한 하루도 부담 없이 남기고, 가벼운 리액션으로 공감받을 수 있는 공간을 목표로 합니다.

## 회원가입 및 이메일 인증 흐름

1. 사용자가 이메일과 비밀번호를 입력합니다.
2. Cloudflare Turnstile로 자동 가입 요청을 방지합니다.
3. Supabase Auth가 회원가입을 처리합니다.
4. Brevo SMTP를 통해 이메일 확인 링크를 발송합니다.
5. 사용자가 링크를 누르면 `/auth/confirm`에서 인증을 처리합니다.
6. 인증에 성공하면 서비스로 이동합니다.
7. 만료되거나 이미 사용한 링크는 인증 오류 페이지로 이동합니다.

로그인 과정에도 Cloudflare Turnstile CAPTCHA가 적용되어 있습니다.

## 비밀번호 재설정 흐름

1. 사용자가 로그인 페이지에서 비밀번호 재설정을 요청합니다.
2. Cloudflare Turnstile로 자동 요청을 방지합니다.
3. Supabase Auth가 비밀번호 재설정 요청을 처리합니다.
4. Brevo SMTP를 통해 비밀번호 재설정 링크를 발송합니다.
5. 사용자가 링크를 누르면 `/auth/confirm`에서 인증을 처리합니다.
6. 인증에 성공하면 `/update-password`로 이동합니다.
7. 사용자가 새 비밀번호를 입력하면 Supabase Auth에 저장합니다.
8. 변경 완료 후 로그아웃하고 새 비밀번호로 다시 로그인합니다.

## 로컬 실행 방법

### 1. 프로젝트 설치

저장소를 내려받은 후 프로젝트 폴더에서 다음 명령어를 실행합니다.

```bash
npm install
```

### 2. 환경 변수 설정

프로젝트 최상위 경로에 `.env.local` 파일을 만들고 다음 환경 변수를 설정합니다.

```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=
NEXT_PUBLIC_TURNSTILE_SITE_KEY=
```

실제 환경 변수 값은 Supabase와 Cloudflare Turnstile 대시보드에서 확인할 수 있습니다.

`.env.local`에는 외부에 공개하면 안 되는 값이 포함될 수 있으므로 Git에 커밋하지 않습니다.

### 3. 개발 서버 실행

```bash
npm run dev
```

브라우저에서 [http://localhost:3000](http://localhost:3000)에 접속합니다.

## 목록 조회 인덱스

목록 조회 조건과 정렬 순서를 점검하고 다음 인덱스를 추가했습니다.

| 테이블 | 인덱스 구성 | 목적 |

| humor_prompts | ends_at DESC, id DESC | 지난 유머 회차의 종료 시간·ID 기준 조회 지원 |
| reports | status, created_at DESC, post_id DESC, reporter_id ASC | 게시글 신고의 상태별 목록 조회 지원 |

| humor_caption_reports | status, created_at DESC, caption_id DESC, reporter_id ASC | 유머 한마디 신고의 상태별 목록 조회 지원 |

적용한 마이그레이션:

- `supabase/migrations/20261018_add_humor_archive_pagination_index.sql`
- `supabase/migrations/20261018_add_report_status_pagination_indexes.sql`

댓글 목록은 기존 `(post_id, created_at)` 인덱스가 사용되는 것을 확인하여 유지했습니다.

검증 내용:

- 비로그인 역할로 댓글과 지난 유머 회차 조회의 실행 계획 확인
- 관리자 역할로 신고 목록의 검토 대기·전체 조회 실행 계획 확인
- 추가한 인덱스의 등록 여부 확인
- 지난 유머 회차 표시·링크와 관리자 신고 필터·페이지 이동 확인

현재 데이터가 적어 지난 유머 회차와 신고 목록의 실행 계획에서는
새 인덱스 대신 순차 스캔이 선택되었습니다.
실행 시간 차이만으로 인덱스의 성능 개선 효과를 판단하지 않았으며,
데이터 증가 후 실제 사용 여부와 성능을 다시 확인할 예정입니다.
신고 인덱스는 상태별 조회를 대상으로 구성했습니다.


## 게시글 댓글 목록

`/posts/[id]`에서 숨겨지지 않은 댓글을 작성 시간 오름차순으로 조회합니다.
작성 시간이 같으면 ID 오름차순으로 정렬합니다.

전체 공개 댓글 수를 별도로 표시하며,
처음에는 서버에서 댓글 10개를 표시합니다.
목록 끝이 화면에 가까워지면 브라우저에서 다음 댓글을 10개씩 추가합니다.
각 조회는 추가 댓글 존재 여부를 확인하기 위해 최대 11개를 요청하고,
화면에 전달할 댓글은 최대 10개로 제한합니다.

추가 조회는 마지막으로 조회한 댓글의 작성 시간·ID를 기준으로 수행합니다.
신고 상태도 해당 댓글들에 한해 조회하고,
두 조회가 모두 성공한 뒤 목록에 반영합니다.

추가 조회 중 중복 요청을 방지하고,
이미 표시된 댓글과 현재 페이지에서 삭제한 댓글은 추가 결과에서 제외합니다.
오류 발생 시 기존 목록을 유지하고 자동 조회를 멈추며,
다시 시도 버튼으로 재조회할 수 있습니다.

댓글 작성란은 목록 위에 배치합니다.
저장에 성공한 댓글은 방금 작성한 댓글 영역에 즉시 표시하고,
추가 조회에서 같은 ID를 가져와도 중복 표시하지 않습니다.
새로고침하면 해당 댓글은 일반 목록에서 작성 시간순으로 조회합니다.

댓글 작성·삭제 시 기존 목록을 유지하며 전체 개수를 갱신합니다.
삭제한 댓글이 마지막 조회 대상이어도 저장해 둔 작성 시간·ID로
다음 조회를 이어갑니다.

댓글 작성·삭제는 실제 처리된 데이터를 확인한 뒤 화면에 반영합니다.
저장 실패 시 입력 내용을 유지하고,
삭제 실패 또는 삭제 대상이 없는 경우에는 안내를 표시합니다.


## 지난 유머 회차 목록

`/humor/archive`에서 종료된 유머 회차를 조회합니다.

종료 시간 내림차순으로 정렬하며,
종료 시간이 같으면 ID 내림차순으로 정렬합니다.

처음에는 서버에서 최신 종료 회차 10개를 표시합니다.
목록 끝이 화면에 가까워지면 브라우저에서 이전 회차를 10개씩 추가합니다.
각 조회에서는 다음 회차 존재 여부를 확인하기 위해 최대 11개를 요청하고,
화면에 추가할 데이터는 최대 10개로 제한합니다.

추가 조회는 마지막으로 표시된 회차의 종료 시간·ID를 기준으로 수행합니다.
조회 중에는 중복 요청을 막고,
이미 표시된 ID는 추가 목록에서 제외합니다.

첫 조회 실패 시 공통 오류 화면에서 다시 시도할 수 있습니다.
추가 조회 실패 시 기존 목록을 유지하고 오류 안내와 다시 시도 버튼을 표시합니다.
오류가 발생하면 자동 조회를 멈추고 사용자의 재시도를 기다립니다.
모든 회차를 조회하면 완료 안내를 표시합니다.

종료 일시는 한국 시간 기준의 고정된 문자열 형식으로 표시하여
서버와 브라우저의 날짜 표현 차이로 인한 Hydration 오류를 방지합니다.


## 관리자 신고 목록

`/admin/reports`에서 게시글·댓글·유머 한마디 신고를 통합 관리합니다.

`admin_report_feed` View로 세 종류의 신고를 통합 조회하며,
`security_invoker` 설정으로 원본 테이블의 RLS를 적용합니다.
View에도 관리자 확인 조건을 적용하여 일반 사용자의 조회 결과를 차단합니다.

신고는 접수 시간 내림차순으로 정렬하며,
접수 시간이 같으면 신고 종류·대상 ID·신고자 ID로 순서를 결정합니다.

목록은 한 페이지에 최대 10건을 표시합니다.
현재 상태 필터의 전체 신고 수와 페이지 번호를 표시하고,
현재 페이지에 필요한 콘텐츠와 프로필만 추가 조회합니다.

이전·다음 이동 시 상태 필터를 유지하며,
다른 상태 필터를 선택하면 1페이지부터 조회합니다.
필터 및 페이지 이동 링크의 자동 사전 로딩은 비활성화합니다.

잘못된 페이지 번호는 1페이지로 보정하고,
마지막 페이지를 넘는 번호는 해당 필터의 마지막 페이지로 이동합니다.
신고 처리로 마지막 페이지가 사라진 경우에도 같은 방식으로 이동합니다.
신고 건수·목록 조회 실패 시 공통 오류 화면에서 다시 시도할 수 있습니다.

새 환경에서는 앱 실행 전에 다음 마이그레이션을 적용합니다.

- `supabase/migrations/20261013_create_admin_report_feed.sql`


## 게시글 사진 Storage 설정

게시글 사진은 비공개 `post-images` 버킷에 저장하며,
`/api/posts/[id]/image` 서버 경로를 통해 제공합니다.

서버는 숨겨지지 않은 게시글의 사진 경로를 조회한 뒤,
Storage RLS 정책을 적용해 사진을 다운로드합니다.
사진 응답에는 `Cache-Control: private, no-store, max-age=0`을 적용합니다.

새 환경을 설정하거나 기존 공개 버킷을 전환할 때는 다음 순서로 진행합니다.

1. 다음 Storage 조회 정책 마이그레이션을 순서대로 적용합니다.
   - `20261008_prepare_post_image_read_policies.sql`
   - `20261009_allow_post_image_download_operations.sql`
2. 서버 사진 조회 경로를 사용하는 앱 코드를 먼저 배포합니다.
3. Supabase Dashboard의 Storage에서 `post-images` 버킷을 편집하고,
   `Public bucket`을 꺼 비공개로 설정합니다.
4. 정상 게시글 사진 조회, 숨김·복원, 업로드·삭제와 기존 공개 URL 차단을 확인합니다.

버킷의 공개 여부는 대시보드에서 별도로 설정합니다.
기존 `20260911_create_post_images_bucket.sql`은 공개 버킷을 생성하는 초기 설정입니다.

Storage 조회 정책은 사진 다운로드와 관련 정보 조회를 허용하며,
본인 파일 삭제에 필요한 조회 권한은 삭제 작업에서만 허용합니다.

유머 주제 사진용 `humor-images` 버킷은 공개 상태를 유지합니다.
